# Decisions

Status values: `DEFAULT` (confirm with the client), `PROVISIONAL` (developer should confirm before build), `FINAL` (safe to build on).

| Date | Decision | Reason | Alternative | Status |
| --- | --- | --- | --- | --- |
| 2026-10-01 | The repository had only `.git` and no app. Scaffolded with `create-next-app` (Next.js 16.3.8, React 19, Tailwind 4) using npm. | No lockfile existed. npm is the installed package manager. The app was generated in `tmp-next` and moved up so `.git` was not overwritten. | pnpm or yarn. Generating into the non-empty root, which `create-next-app` refuses. | FINAL |
| 2026-10-01 | Node.js line is 24. `.nvmrc` is `24.12.0`. `engines.node` is `>=24.12.0 <25`. | That is the Node version running on this machine, and Node 24 is the current LTS line as of this date. | Pinning the previous LTS (22), which would not match the machine used to scaffold. | FINAL |
| 2026-10-01 | Package name is `adyas-project`. | The folder name is the only project name available. It is an npm name only, not a public brand claim. | Leaving the temporary name `tmp-next`. | FINAL |
| 2026-10-01 | `.gitignore` keeps create-next-app's `.env*` rule and adds `!.env.example`. | `.env*` would also ignore the committed template. Real env files stay ignored. | A narrower ignore list that might miss `.env.development.local` or similar. | FINAL |
| 2026-10-01 | No Supabase, Razorpay, Google, zod, or timezone packages were installed in this phase. | This phase is scaffold and documents only. | Installing clients now, before the modules that use them exist. | FINAL |
| 2026-10-01 | Security headers are specified in `docs/ARCHITECTURE.md` and are not added to `next.config.ts` yet. | Header and CSP choices affect Razorpay Checkout and belong with the payment phase, not the empty scaffold. | Adding a strict CSP now that later has to be undone for Checkout. | FINAL |
| 2026-10-01 | Empty feature folders (`src/lib`, `src/components`, `supabase/migrations`) were not created. | The tree in the architecture doc is the contract. Empty directories are easy to get wrong before implementation. | Creating the full tree with placeholder files. | FINAL |
| 2026-10-01 | Payment is the full session fee up front, in one Razorpay order. No deposits or partial payments. | One payment has one confirm path and one amount in paise. Partial payments need extra states this site does not have an admin UI to manage. | A deposit plus a balance collected later. | DEFAULT - confirm with client |
| 2026-10-01 | Cancellation notice is 24 hours before the session start. Inside that window the fee is not refunded automatically. There is no self-serve cancel button in v1. | There is no admin dashboard, and an automatic Razorpay refund can send money without a person checking the policy. The customer asks via the contact page; a person refunds in the Razorpay dashboard and the row can move to `refunded`. | Self-serve cancellation with an automatic refund. A stricter 48-hour notice. | DEFAULT - confirm with client |
| 2026-10-01 | Rescheduling is not self-serve in v1. It is a cancellation plus a new booking, under the same 24-hour notice. | A reschedule has to release one slot and hold another without a double charge. That is a second product flow. | An in-app reschedule that moves the calendar event and keeps the payment. | DEFAULT - confirm with client |
| 2026-10-01 | Sessions are online. The calendar event says so and does not include an invented address or meeting link. No Google Meet is created automatically in v1. | A physical address would be an invented claim. Meet creation is a separate API failure mode. The practitioner adds the real link on the calendar event. | In-person only, or both modes as a customer choice. | DEFAULT - confirm with client |
| 2026-10-01 | Working hours are Monday–Saturday 10:00–18:00 in `Asia/Kolkata`. Sunday is closed. A session must end by 18:00. The buffer may extend past 18:00. | These are the hours requested as the default. The last slot of the day does not need a following client, so the buffer need not fit inside closing time. | A lunch break, Sunday hours, or requiring the buffer to end by 18:00. | DEFAULT - confirm with client |
| 2026-10-01 | Buffer between commitments is 15 minutes. Slot starts are every 30 minutes. Minimum notice is 12 hours. Maximum advance booking is 60 days. | 15 minutes was requested. A 30-minute grid is coarse enough to read on a phone and fine enough for 60- and 90-minute sessions. 12 hours avoids same-day surprise bookings. 60 days is long enough to plan and short enough to compute. | 15-minute grid, 24-hour notice, or 28-day horizon. | DEFAULT - confirm with client |
| 2026-10-01 | Two bookable session types, both placeholders until real names and fees are supplied: 60 minutes and 90 minutes. Prices live in server code, in integer paise, and checkout must refuse a non-positive amount. | The product needs two types and no real fees were given. A zero price would create a free paid-booking path. | One session type, or publishing example rupee amounts on the marketing pages. | DEFAULT - confirm with client |
| 2026-10-01 | Existing Google Calendar busy periods block slots. The site reads free/busy only and never event titles, attendees, or descriptions. | The practitioner's other commitments must not be double-booked, and those event details are private. | Ignoring the calendar and blocking only site bookings. | DEFAULT - confirm with client |
| 2026-10-01 | No email or SMS notifications in v1. Confirmation is the on-site page plus the calendar event. | Notifications were specified as optional and only if requested. They add an email vendor, templates, and more personal data in logs. | Transactional email for confirmation and reminders. | DEFAULT - confirm with client |
| 2026-10-01 | Google Calendar auth is OAuth with one stored refresh token for the practitioner's own Google account. The OAuth consent screen must be set to **In production**, not Testing. | Official Google documentation: an external consent screen left in Testing issues refresh tokens that expire after 7 days (unless the only scopes are profile, email, or openid). Calendar scopes are not in that exception. Production publishing avoids that 7-day expiry. A personal Gmail account can create events with attendees; a service account cannot invite attendees unless it has Workspace domain-wide delegation, which a typical independent practice does not have. | A service account with the calendar shared to it. Better token hygiene, but customer invites do not work on personal Gmail. | PROVISIONAL |
| 2026-10-01 | If Google Calendar cannot be reached, availability fails closed. The API returns a service-unavailable error, and the page says availability is temporarily unavailable. It does not return an empty slot list. | An empty list means "nothing is free". Showing slots without the calendar risks a double booking. A failed calendar write after payment does not un-confirm the booking (see architecture). | Showing slots from the database only when Google is down. | PROVISIONAL |
| 2026-10-01 | Unpaid holds expire after 15 minutes. If payment is captured after expiry and the slot is still free, the booking is confirmed. If another booking holds the slot, this booking is not confirmed, `payment_status` becomes `refund_pending`, `needs_manual_review` is set, and nobody is double-booked. Refunds are manual in the Razorpay dashboard in v1. | The brief requires a 15-minute hold and forbids a silent double booking. Automatic refunds without a review step can return money for the wrong payment. | Auto-refund as soon as the conflict is detected. Keeping the later payer and cancelling the earlier hold. | PROVISIONAL |
| 2026-10-01 | The customer confirmation URL uses an unguessable token. The database stores only its SHA-256 hash. | A leaked database backup should not be a list of working confirmation links. | Storing the raw token, which is simpler to debug and weaker if the database leaks. | FINAL |
| 2026-10-01 | Slot arithmetic will use Luxon when the availability phase starts. It is not installed yet. | Slots are computed in an IANA timezone and stored in UTC. `Asia/Kolkata` has no DST, but the timezone is configurable, so a fixed `+05:30` offset is the wrong tool. Luxon uses the IANA database. | `date-fns` with `@date-fns/tz`, or Node's still-maturing `Temporal`. | PROVISIONAL |
| 2026-10-01 | The browser never talks to Supabase. The server uses the service-role key. Row level security is enabled with no policies for the public roles, which denies them. | There are no user accounts. A browser Supabase client would be another key to leak. Deny-by-default RLS still protects a leaked anon key. | RLS policies that allow anon reads of slots. | FINAL |
| 2026-10-01 | The only `NEXT_PUBLIC_` variable is `NEXT_PUBLIC_SITE_URL`. The Razorpay Key Id is server configuration and is sent to Checkout in the booking response, because Checkout cannot open without it. | The Key Id is designed by Razorpay to be public, but it is still not given a `NEXT_PUBLIC_` name, so a secret is harder to "make public" by mistake. | `NEXT_PUBLIC_RAZORPAY_KEY_ID` baked into the client bundle. | FINAL |
| 2026-10-01 | Abandoned holds are expired inside the availability and create-booking transactions. A daily cron route is only a backup. | Vercel Hobby cron is not a reliable per-minute sweeper. Correctness has to live in the request that reads or writes the slot. The database exclusion constraint keeps treating a `pending` row as blocking until its status changes. | Depending on a frequent cron, which the free tier may not run. | FINAL |
| 2026-10-01 | Rate limiting uses a small Supabase table, not a new Redis vendor. | The free Vercel tier has no shared in-memory counter across serverless instances. The database is already in the stack. | Upstash Redis, which is another account and dependency. | PROVISIONAL |
| 2026-10-01 | Default create-next-app marketing files (`AGENTS.md`, `CLAUDE.md`) were left in place. Unused template SVGs in `public/` were removed with the boilerplate homepage. | Next.js rewrites `AGENTS.md` during `next dev`. The SVGs were only used by the template homepage. | Deleting `AGENTS.md`, which the framework may add back as an uncommitted change. | FINAL |
